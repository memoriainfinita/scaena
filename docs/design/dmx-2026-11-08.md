# DMX of the luminaires (2026-11-08)

Origin: review of 2026-11-08, accepted by the user; USITT 4.5.2, 4.5.3 and 4.6.2.

## Data

- `scripts/import-ofl.mjs` now keeps each fixture's modes as `[name, channels]`, counting matrix inserts. Modes it cannot count are left out
- `Luminaire` gets two optional fields, no format version change: `dmxMode` (the name of a mode of its model) and `dmxSlots` (channels typed by hand, for models without modes)
- Choosing a model picks its first mode; a model without modes clears both
- Channels taken: `dmxSlots`, else the chosen mode's count, else unknown (counted as 1 when looking for overlaps)

## Behaviour

- `dmxOverlap` compares ranges (address to address + channels − 1) inside each universe instead of equal addresses
- New rule `dmxBeyond`: a fixture that runs past channel 512
- **Address DMX** (Lights, Instruments): in rigging order (the one **Number the instruments** uses) gives consecutive addresses from universe 1, moving to the next universe when a fixture would not fit. Only fixtures with a known channel count; conventionals on dimmers are left alone. One undo step

## Output

- Instrument schedule report: new DMX mode column, written as `name (channels)`
- New report **DMX addresses**, by universe and address: universe, start, end, unit, instrument, model, mode, mount
- New report **IP addresses**: every element with an IP, with its type, position and note
- New document section **DMX and IP** with both tables; templates add it when there is an address or an IP to list

## Not included

Control protocol per fixture or universe (sACN, Art-Net): proposed by USITT 4.5.3, separate decision.
